1. BIG PICTURE
--------------

  - ONE global "session": who is logged in right now (Context).
  - ONE tab navigator: Login | Signup | Home (same bar for everyone).
  - Custom floating tab bar enforces guest vs signed-in rules.
  - Accounts and session can survive app kill via AsyncStorage (milestone D).

Flow when user taps Login:

  LoginScreen -> useAuth().login(email, password)
       -> validation.ts
       -> authStore.verifyCredentials (Map loaded from disk)
       -> setUser + saveSession (AsyncStorage)
       -> toast + navigation.navigate('Home')


2. APP ENTRY AND PROVIDER TREE (App.tsx)
----------------------------------------

Outermost to innermost:

  SafeAreaProvider
  AuthProvider                 user, isAuthReady, login, signup, logout
  AuthLoadingGate              spinner until AsyncStorage hydrate finishes
  ModalProvider                error popups
  ToastProvider                success / tab hint messages
  AppNavigation                NavigationContainer + ref + RootNavigator

Important order:

  - AuthProvider wraps navigation so FloatingTabBar can call useAuth().
  - AuthLoadingGate waits for isAuthReady before showing UI (avoids flash).
  - Navigation lives in AppNavigation.tsx (not directly in App.tsx).

3. REACT CONTEXT API — AuthContext
----------------------------------

Pattern:
  createContext -> AuthProvider -> useAuth() in any child.

Public API:

  user: AuthUser | null     { name, email } — never includes password
  isAuthReady: boolean      false until hydrate from AsyncStorage completes
  login(email, password)    -> AuthActionResult
  signup(name, email, pw)   -> AuthActionResult (does NOT log you in)
  logout()                  clears session in memory + AsyncStorage

AuthActionResult:
  success, message?, field? ('name' | 'email' | 'password')

login success:
  setUser -> saveSession(@context-auth/session)

logout:
  setUser(null) -> clearSession (remove session key only)

signup success:
  registerUser -> persists @context-auth/users
  does NOT setUser — user must use Login tab

On mount (cold start):
  hydrateUserRegistry() then loadSession() then isAuthReady = true
  If hydrate throws (e.g. native module missing), app still opens; dev warns.


4. TWO KINDS OF STORED DATA (READ THIS FOR LOGOUT / KILL APP)
------------------------------------------------------------

  A) SESSION — "am I logged in right now?"
     - In memory: AuthContext user
     - On disk: @context-auth/session  ->  { name, email }
     - Login writes it; logout removes it
     - Password is NEVER in session

  B) ACCOUNT REGISTRY — "which emails exist for this demo?"
     - In memory: authStore Map
     - On disk: @context-auth/users  ->  [{ name, email, password }, ...]
     - Signup appends; logout does NOT delete accounts
     - Demo-only plain passwords (not production safe)

  C) FORM FIELDS — separate from Context
     - LoginScreen / SignupScreen use local useState for inputs
     - Logout does not clear those fields (tabs often stay mounted)
     - iOS autofill may refill email/password (system, not this app)

What happens when you...

  Logout then login again (app still running):
    Session gone; accounts still in Map + disk -> login works.

  Login -> kill app -> reopen:
    Session restored from disk -> Home (via AppNavigation).
    Accounts also on disk -> still consistent.

  Logout -> kill app -> login:
    No session -> opens as guest on Login.
    Accounts still on disk -> login with same credentials works.

  Signup only -> kill app (never logged in):
    No session key -> guest on Login.
    Accounts on disk -> can login.


5. authStore + authStorage
--------------------------

authStorage.ts (AsyncStorage wrapper):
  loadSession / saveSession / clearSession
  loadUserRegistry / saveUserRegistry

authStore.ts (runtime Map):
  hydrateUserRegistry()  — call once at app start
  registerUser()         — updates Map + saveUserRegistry()
  verifyCredentials()  — login check against Map

Package: @react-native-async-storage/async-storage@2.x (RNCAsyncStorage).
After install or version change: cd ios && pod install && yarn ios (full rebuild).
Metro reload alone is NOT enough for native modules.

7. COLD START AND RESTORING HOME (navigation ref)
-------------------------------------------------

Problem we fixed:
  Calling useNavigation().navigate('Home') too early throws
  "The navigation object hasn't been initialized yet" after kill + reopen.

Solution (AppNavigation.tsx):
  - createNavigationContainerRef<MainTabParamList>()
  - NavigationContainer ref={navigationRef} onReady={...}
  - When isAuthReady && user: navigate to Home only if ref.isReady()
  - onReady runs when the tab navigator has mounted

Do NOT navigate to Home from a component that sits outside the navigator
without using this ref pattern.


8. FLOATING TAB BAR — GUEST VS SIGNED IN + TOASTS
-------------------------------------------------

File: src/components/FloatingTabBar.tsx

Always three labels: Login | Signup | Home.

Guest (user == null):
  - Home tap -> toast "Please sign in to access Home." -> navigate Login
  - Login / Signup -> normal tab switch

Signed in (user set):
  - Home -> active screen
  - Login / Signup -> locked (muted style, small bounce, NO navigation)
  - Login / Signup tap -> toast
    "You are signed in. Use Home or log out first."

LoginScreen / SignupScreen also use useFocusEffect:
  if user exists -> navigate Home (backup if tab state desyncs).

HomeScreen: if no user on focus -> navigate Login.


9. SCREEN BEHAVIOURS
--------------------

LoginScreen:
  email, password (Feather eye toggle)
  login() -> modal on error; toast + Home on success
  Go to Login N/A

SignupScreen:
  name, email, password
  signup() -> modal on error
  success -> toast, clear password, navigate Login
  "Go to Login" -> PrimaryButton variant="outline" (black border, no fill)

HomeScreen:
  marketing banner, hero, draggable carousel, account card, Logout
  logout() -> clear session -> navigate Login

11. DEBUGGING CONTEXT (VS REDUX)
--------------------------------

Redux gives you middleware (e.g. logger) + Redux DevTools (actions, time travel).

Context has no built-in store or dispatch. Equivalent approaches:

  React DevTools (recommended for RN):
    npx react-devtools
    Select AuthProvider -> expand hooks -> watch user (null vs object)
    Or select HomeScreen / FloatingTabBar -> see useAuth consumer state

  Console:
    Log in login/signout/setUser or useEffect on [user] in AuthProvider

  Breakpoints:
    AuthContext.tsx, authStore.ts, FloatingTabBar onPress

  useReducer + dev wrapper (optional):
    Same idea as redux-logger: log prev/action/next in one reducer

You do NOT get Redux DevTools for Context unless you bridge a fake store.

React DevTools hooks may show as "Anonymous" — expand them to see values.


12. TYPICAL USER JOURNEYS
-------------------------

New user:
  Signup -> toast -> Login tab (still guest)
  Login -> toast -> Home (session saved)

Return after kill app (was logged in):
  Spinner -> Home restored (session + AppNavigation ref)

Signed-in user:
  Login/Signup tabs visible but locked + toast if tapped
  Logout -> Login tab, session cleared, accounts remain

Guest taps Home:
  Toast + Login tab
